# דוגמאות: מה הסקיל מייצר בפועל

כל תיקייה כאן היא הרצה אמיתית של `/present` על חומר קיים. יש בה את הקובץ המקורי, את הקובץ שהסקיל ייצר ואת דוח השיפור. המטרה היא שאפשר יהיה לבקר את התוצרים ולא רק את ההוראות.

| דוגמה | מצב | לפני → אחרי |
|-------|-----|-------------|
| [`finance-automation-training/`](finance-automation-training/) | IMPROVE | 10 שקפים → 13. ציון 2/26 → 23/26 |

## מבנה כל דוגמה

```
<example>/
├── before/
│   ├── <deck>.pptx        # הקובץ המקורי, כמו שהגיע
│   ├── slides/*.png       # כל שקף כתמונה, 1280×720
│   └── slides.md          # טקסט השקפים + הערות הדובר + קישור לכל תמונה
├── after/
│   ├── <deck>_improved.pptx
│   ├── slides/*.png
│   └── slides.md
└── improve-report.md      # הדוח שהסקיל כתב: ציון, תיקונים, מה לא שונה
```

`slides.md` קיים כדי שמי שלא יכול לפתוח PPTX (למשל סוכן AI) יוכל לקרוא את כל התוכן ולראות את התמונות.

## בריף לסוקר חיצוני (Grok או כל מודל אחר)

אתה מקבל ריפו של סקיל לאימון הרצאות. הסקיל עצמו נמצא ב-`SKILL.md`, וחומרי הרקע ב-`references/`. בתיקייה הזו יש תוצרים אמיתיים שלו.

**המשימה:** לשפר את התוצרים, ודרכם את הסקיל.

1. **תבקר את `after/`** של כל דוגמה מול `before/` ומול `improve-report.md`:
   - מה עדיין חלש בשקפים? תפנה למספרי שקפים.
   - האם הפתיחה, הסיום ונקודות המעורבות בהערות הדובר באמת יעבדו מול צוות כספים?
   - האם הציון בדוח הוגן, או שהסקיל נותן לעצמו ציון גבוה מדי?
2. **תציע גרסה משופרת** של הדוגמה: טקסט לכל שקף, הערות דובר, וכיוון ויזואלי לכל שקף.
3. **תציע שינויים ל-`SKILL.md`** שהיו מונעים את החולשות שמצאת. למשל: בדיקה שחסרה בטבלת הציון, כלל שהסקיל לא אוכף, או שלב שמייצר תוצר חלש.
4. **מה כבר ידוע כחלש** (פירוט ב-`improve-report.md`): אין תמונות, עיצוב ברירת מחדל, גופן שהתחלף אחרי סימון העברית, מספרים בלי מקור, וגיבור הסיפור מופיע רק בהערות.

**כללים:**
- עברית בכל התוכן שמיועד לקהל.
- לא להמציא נתונים. מספר בלי מקור מסומן `[מקור חסר]`.
- לא לשנות את השיטה (טבלת השכנוע, Rule of Three, סולם ההשתתפות) בלי לנמק.
- הפורמט להחזרה: diff ל-`SKILL.md`, ו-`slides.md` חדש לדוגמה.
